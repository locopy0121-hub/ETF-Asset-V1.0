# TF Asset V4.0.61 (40061)

Base: V4.0.60, commit 0bd6c5e6f28e4dc24b4299492cb989313c9efd76.

The reported post-upgrade slowdown and white screen require device confirmation. Inspection identified two concrete startup/performance defects: local readiness waited for native market and Keystore promises, and every source clock update serialized the entire security catalog into AsyncStorage. Local hydration now completes independently of native responses. Native results still apply when available. Market-cache writes use a serialized latest-only queue with a five-second write window; quote reception is unchanged. An outer native-control recovery screen catches React provider/render failures without clearing stored data. Startup taking over ten seconds writes a diagnostic event and displays a waiting message.

Market search results and selected-security summaries support add/remove watchlist. A separate persisted list preserves Chinese display names and prevents duplicates. Market and home wall display watchlist quotes with source time, price, change, prior close and volume. Home wall offers holdings/watchlist/all. The floating Monitor offers the same source choices, deduplicates mixed rows and labels holdings/watchlist membership. Watch-only rows suppress accounting fields and never enter finance calculations or totals. Foreground and background subscriptions union held, searched and watched symbols. Optional watchlist read/parse failure cannot stop background accounting projections; malformed foreground watchlist data is preserved in a recovery copy before reset.

Protected Settings shell: only the Monitor child import and version/build metadata changed. Existing controls, classifications and account settings remain protected by their byte comparison gate. Finance formulas are unchanged.

Validation: TypeScript; inherited V4.0.60 suite; new watchlist/model and actual provider lifecycle tests; native source selection, dedupe, labels and accounting suppression tests. No attached Android device/emulator is available in this environment, so actual upgrade-time performance and the original white-screen symptom remain device acceptance items. Cloud CI/QA APK must succeed before delivery.
