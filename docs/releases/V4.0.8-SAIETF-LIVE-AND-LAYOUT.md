# TF Asset V4.0.8 SaiETF 行情中心與設定實畫面一致性修護

版本 4.0.8 / 40008，延續 TF Asset V3.2.49 基底及 V4.0.1–V4.0.7 修護。

## 使用者回報

1. 資產總覽設定預覽的 27,690 已套用損益色並靠右，返回首頁後卻變成黑色、靠左。
2. 2026-10-08 09:03 台北盤中，首頁顯示「估值待核對」，沒有跟隨 SaiETF 行情中心即時總市值。
3. TF Asset 舊行情中心規則必須由 SaiETF 行情中心完整取代。

## 根因與修護

- 頁面設定把值寫入 `display.layoutTargets`，但首頁的 `InspectableTarget` 只讀維護工程師覆寫。現在先合併已儲存頁面設定，再以個別維護覆寫為最高優先；損益色、左右／置中對齊、字級及手動 tone 在預覽、套用、重啟後一致。
- App 原本只在整批 HTTP 備援查詢完成後取得原生 snapshot；慢速或卡住的未解析標的會延遲已到達 Memory Hot Store 的 Fugle／TWSE 行情。現在每秒獨立讀取 SaiETF 記憶體快照，並以 `queriedAt` 拒絕較晚返回的舊批次回應。
- 原生 MarketDataCenter 每接受一個 provider 行情即發布到 Memory Hot Store；仲裁與發布同鎖，避免較早的輪詢值覆寫較新的 Fugle tick。不再等所有 unresolved symbol 跑完 Yahoo 才發布；讀取 snapshot 不再與 refresh 共用整個 runtime 鎖。
- `readUnifiedMarketData` 帶入實際追蹤代號，缺檔狀態與畫面持股一致；持股移除後訂閱清單也會真正移除，不再永久累加舊代號。
- 移除 TF Asset 退役 TypeScript `MarketCore`、`MarketProviders`、`MarketPersistence`、`FugleWebSocketProvider`，並移除 JS／Native 對 Market Core SQLite 的旁路讀寫及未使用 backend URL 設定。
- App 行情契約移除已由 SaiETF 淘汰的 Shioaji 來源。唯一即時順序為 Fugle WebSocket → TWSE MIS → Yahoo → 同盤 Memory Hot Store；前盤資料盤中只供診斷，不得完成估值。
- Widget 舊的獨立 HTTP import 與舊時間解析器移除；Widget／Monitor 繼續讀 SaiETF 持久化快照與 Finance snapshot。

## 自動驗證

- 預覽 → 套用 → JSON 儲存／重啟 → 首頁實際 `InspectableTarget`：兩套漲跌模式、損益色、左中右對齊、字級、手動狀態及個別維護覆寫優先序。
- 慢速 HTTP pending 時 Memory Hot Store 行情可進入 App，並由正式 FinanceRuntime／canonical ledger 投影更新總市值；下一 tick 可再更新，較晚舊回應不可倒退；前盤資料盤中仍拒絕。
- 原生測試新增：一個標的卡在慢速 Yahoo 時，另一個標的 TWSE 行情即時發布；期間較新的 Fugle tick 不可被批次舊值回滾。
- `test:v4_0_8` 完整繼承回歸、本版三項實際行為測試及 TypeScript 通過。
- `canonicalLedger.ts`、`etfCalculators.ts`、`CORE_LOCK.md` 未修改。

## 裝置驗收

1. 台北 09:00–13:30 持有標的有 Fugle／TWSE 新成交時，資產總覽由「估值待核對」切換為即時總市值，後續行情持續更新。
2. 任一標的備援逾時時，其他已取得標的仍更新；總資產僅在全部持股具有效行情後發布，部分覆蓋不可冒充完整總數。
3. 於頁面設定把資產總值設為損益色、靠右，按「套用」返回首頁並重啟 App，顏色與對齊必須與預覽相同。
4. 移除／新增持股後，Fugle 訂閱清單相應移除／新增；來源時間、DELAYED／STALE 與未解析代號保持真實。
5. Widget、Monitor、首頁、庫存與圖表顯示同一來源版本及價格。真機網路、Fugle API Key、供應商回應與 Android 背景生命週期仍須以 QA APK 驗收。
