# TF Asset V4.0.3 損益色修護

## 問題與修正

V4.0.2 的持股表、詳情、首頁損益明細與歷史視窗使用靜態 tokens，KPI 預設損益色來自主題；全域設定雖保存，部分實際畫面沒有訂閱。profitColorMode 也未被顏色解析函式讀取。

- 統一正負對應解析：一般正值用獲利色、負值用虧損色；反向模式交換兩色，零值用中性色。
- 以 SettingsRuntime 訂閱更新實際元件；設定變更及儲存設定載入後會重新渲染。
- 首頁昨日／今日／持股總損益、KPI、損益明細、持股表／備援清單／詳情、歷史損益與 K 線採用設定來源。
- 元件固定色、關閉損益色、透明度及既有版面保留；連動的背景／邊框／效果也透過共同 linkedColor 解析正負對應。
- 持股表零損益／零報酬率顯示中性色。此修正只改 display tone，不改任何財務數值。
- 版本 4.0.3 / 40003。延續 V4.0.2 行情修正與 V3.2.49 帳務底版。

## 驗證

已先重現兩個失敗：反向模式仍回傳原獲利色；ValueRow 改設定後仍回傳 #E5484D。修正後測試通過。

- `scripts/v4_0_3-profit-colors.test.ts` 驗證正負對應、零值及关闭連動保留自訂色。
- `scripts/v4_0_3-profit-render.test.cjs` 執行實際元件函式及其 JSX，驗證首頁總覽、KPI、損益明細、持股表及備援清單在兩模式下採用即時設定，並驗證負數、零值、KPI 固定色優先權。此測試以 host／hook stub 隔離 React Native 環境，不等同真機像素截圖。
- 舊持股表的 SHA 鎖仍保留：只移除新增的訂閱 import／hook，再核對原 V3.0.1 SHA，避免版面被意外重寫。
- `npm run test:v4_0_3` 包含全部繼承的 V3.2.49／V4.0.2 回歸；CI 與 QA APK 均要求此套測試。
- 帳務核心 `canonicalLedger.ts`、`etfCalculators.ts` 及 `CORE_LOCK.md` 未修改。

真機仍需驗收：變更全域三色及正負對應，檢查首頁與持股表立即更新；重新啟動後設定仍生效；關閉單一元件損益色時固定色維持。行情同步延續 V4.0.2，需另以實際來源時間與價格驗證。
