Base: V4.0.13 / 57d7643c5cf91af9877367b4c3d5a988fa729152.

## Locked acceptance checklist

- News card opens its HTTPS article in the existing modal, including articles without extracted summaries.
- Existing app theme, security name/source and close control remain available.
- Native WebView receives the original URL; article HTML and images are rendered by the publisher page.
- Progress indicator, 25-second load timeout and retry are available. An error followed by loadEnd stays visible.
- Refresh/retry reloads the current native page and retains navigation history.
- Android back goes back in webpage history before dismissing the reader; close always dismisses.
- New-window links navigate in the same WebView and retain history; no accumulating news windows.
- Invalid URLs and automatic external-app navigation are blocked. Explicit external opening handles failure.
- Modal dismissal unmounts the WebView and clears its timeout.
- Renderer termination removes the dead browser without issuing native commands; retry creates a new one at the current article.
- Root app, settings, backup metadata and both native build workflows identify 4.0.14 / 40014.
- Native generated build workspace includes react-native-webview 13.16.1.

## Verification

The new real React renderer test (native views/commands replaced at the test boundary) failed against the original modal before implementation. It covers inline original URLs, error followed by loadEnd, retry, native reload dispatch, retained instance/history, Android back, explicit close, target=_blank navigation, invalid URLs and unmount.

Inherited test suites include canonical accounting, live market data, Widget/Monitor native presentation and ETF constituents. The local tsx CLI cannot bind its IPC socket; the same suite commands are run using node --import tsx without dropping tests. Expo dependency version is also verified against expo/bundledNativeModules.json.

This is a QA artifact. Android hardware rendering, actual publisher connectivity, image layout, device navigation and system safe-area appearance require device acceptance. Build success is not a claim of those checks passing. No market data or immutable finance code was changed.
