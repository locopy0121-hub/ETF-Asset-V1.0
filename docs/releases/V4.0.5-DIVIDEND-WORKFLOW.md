# TF Asset V4.0.5 股息流程修護

版本 4.0.5 / 40005，延續 V4.0.4；原 TF Asset V3.2.49 帳務與原生 Market Core 基底保留。對應檢整 P0-03 / P0-04。

## 修護內容

- 日期必須為真實日曆日期，拒絕 2/31、非閏年 2/29；已填日期須依最後購買日 < 除息日 ≤ 基準日 ≤ 配發日排序。不推測未公告日期。
- 切換代號清空前一代號的名稱、股數與公告資料。已公告資格日期以原 canonical ledger 回看歷史股數；除息日當日買入不納入。未來日期、無公告或無可用資格資料需手動核對。
- 預告、已確定、已入帳分開。預告只保存事件，不改現金；確認要求配發日、每股股息、符合配息股數完整；到期後仍需明確確認實際收款才轉入 canonical ledger。
- 編輯已確認事件須重新確認；已入帳事件由正式帳務 ID 推導，不可直接修改或刪除事件；入帳重播／重複按鈕不增加第二筆現金。
- AI 再匯入不覆寫已核對事件；同代號除息日或配發日相同時提示編輯，不重複新增。正式帳務同代號同配發日即使金額或股數不同也提示核對。
- AI 公告入口一律儲存預告，不再以除息日代替未知配發日，也不把推算股數視為已核對。
- entries 與 dividendPlans 同一 React 狀態、同一原帳本 storage payload 保存，備份亦包含預告。舊帳本無新欄位仍可讀；損壞預告保留原內容並阻擋事件操作，備份匯入先驗證再寫入。
- 舊帳本已存在的未來股息不改寫數字，畫面標記需核對；新增實收入口禁止未來日期。

## 裝置驗收

1. 升級既有帳本與設定保留，預告新增後關閉重開仍存在。
2. A 代號切換至未持有 B，名稱／股数／日期不得殘留 A。
3. 先買 100 股，除息當日再買 50 股，日後賣 25 股；資格股數應為 100，不是今日 125。
4. 預告、已確定在到期前後皆不自動入帳；確認實際收款一次後淨現金增加，再點不可重複。
5. AI 未公告配發日只形成預告；補齊資料後確認入帳。
6. 月曆預告／確定狀態與正式實收月年統計一致；螢幕縮放、動態字體、深淺色需装置確認。
7. 備份／重啟預告與已入帳關聯保留；損壞預告提示，原內容不被空清單覆寫。

本版不宣告全部檢整完成。股票／ETF 支援邊界、FrameCard 損益 tone、備份還原後整體 runtime 同步仍在後續清單。
