# V4.0.54 — Connect floating Monitor to the existing background writer

The user screenshot shows the native floating Monitor over another app, not a desktop Widget. Its current background path has three gaps: App.tsx skips foreground Monitor synchronization while background; headless task writes Widget snapshots but Native syncWidget does not repaint Monitor; the foreground writer starts only with desktop Widgets. A static screenshot cannot establish continuous quote freshness.

## Scope / acceptance
- Actually visible Monitor or installed desktop Widget is sufficient for the existing trading-session foreground writer. No second quote connection, polling or finance implementation.
- After a canonical background surface snapshot is saved, repaint only an existing background Monitor; preserve its configuration, mini/normal mode and close state. Foreground configuration remains owned by App.
- Removing last desktop Widget preserves writer while Monitor is visible; destroying last Monitor without Widgets stops writer. Closed windows must never be reopened by ticks.
- Runtime policy tests cover desktop-only, Monitor-only, both and neither; foreground handoff and background repaint callbacks. Source wiring smoke is separate.
- Inherited native market tests, 144 regression gates, TS, GitHub backend/quality/native QA build, APK version/hash/permissions/bundle registration checks.
- Device pending: three surface combinations during permitted Taipei hours, Home/app switch, new trade + exchange source timestamp, closing one/both consumers, mini/normal layouts. Automated tests are not Android device proof.
