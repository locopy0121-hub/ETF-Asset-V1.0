# TF Asset V4.0.44 — SaiETF Market Center contract restoration

Source of truth: [SaiETF Market Update Center Core Lock](https://github.com/locopy0121-hub/Saietf_V1.0.1/blob/main/core/market/UPDATE_CENTER_CORE_LOCK.md) and [SaiETF Market Data Synchronization Policy](https://github.com/locopy0121-hub/Saietf_V1.0.1/blob/main/docs/MARKET_DATA_SYNC_POLICY.md).

## Scope
- Restore frozen authoritative SaiETF MarketDataCenter and MarketArbitrator implementations; do not invent a TF-only arbitration strategy.
- Foreground synchronization cadence follows SaiETF: every 1 second in Taipei's live session and every 30 seconds after hours. The *client refresh cadence* never bypasses the provider's rate limits, 429/403 cooldown or circuit breaker.
- Market's Memory Hot Store (not UI or SQLite) remains the single quote-selection source. Fugle streaming takes precedence while fresh; TWSE MIS and Yahoo remain fallbacks.
- Prevent cross-session previous-close carryover when live Fugle quote payload omits a previous-close value. Unknown previous close remains explicitly unverified until a same-session authoritative reference is available.
- Preserve Account/Ledger, Settings and existing all-app chart/editor behavior.

## Frozen-core compatibility adapter
- SaiETF locked MarketDataCenter intentionally has no TF-only restorePersistedQuotes method. The native adapter creates a bounded (seven-day) MemoryMarketStore from trusted persisted snapshots before constructing the center.
- Native runtime replays only valid newer Fugle streaming quotes after slow HTTP polling completion, protecting the UI against batch-publication races without editing SaiETF's immutable core.
- Native bridge regression tests now validate the frozen-core behavior plus external adapter, rather than the retired TF-only mutation APIs.
