# V4.0.57 — Fugle subscription recovery and external quote clock

Baseline V4.0.56 d9c01b9d3b57d828806f7f8aef7c0d34c49575be. Backup branch backup-v4.0.56-pre-fugle-recovery-20261014. User requests continuation of intraday no-update investigation and HH:mm:ss on external Widget and floating Monitor.

## Evidence and repair
Phone MARKET_FLOW showed zero accepted Fugle trades while 984 snapshots were applied and 1208 renders completed. A later source panel showed COOLDOWN. Those snapshots also include provider-health changes, so they do not prove a working trade feed. The phone's actual rejection/transport error was not preserved and remains unconfirmed.

Production-provider tests reproduce: auth/heartbeat reported healthy without trade ACK; repeated auth reset retry backoff after failed subscriptions; changing symbols bypassed retry cooldown; replacements added symbols before old server subscriptions were released. Independent review found an additional overlap when old subscribe ACK was still in flight. Fix preserves exponential retry across auth-only attempts, gates health/recovery reset on full desired trade ACK coverage, respects retry deadline, and waits for obsolete pending/active subscriptions and unsubscribe ACK before additions. Missing unsubscribe ACK has the same bounded recovery timeout as missing subscribe ACK. Successful ACK coverage and genuine nontrial trade callback are tested.

## Source diagnostics
The existing diagnostic journal receives separate MARKET_SOURCE rows on connect/auth/subscribed/unsubscribed/pause/error/disconnect/timeout. Native source history is bounded to eight records separately from eight MARKET_FLOW records. Rows contain fixed categories, numeric code/close code where supplied, auth/subscription counts, retry/deadline, packet/rejected counts and last valid trade receipt time. No API key, raw server message, symbol/price or finance payload is saved. Source rows do not append JS render counters, keeping the existing 400-character detail limit.

## External source clock
Widget toolbar and normal/mini floating Monitor show latest selected holding source time as HH:mm:ss in Asia/Taipei. Individual native updatedAt fields also include seconds. Missing source time shows --:--:--; render/generatedAt time is not substituted. Clock follows canonical snapshot events and retained last data outside schedule; no one-second price or clock polling is added.

There is no connected phone/emulator; continuous actual market reception, OEM background lifetime and compact-window visual acceptance still require device validation. This is a repair of reproduced defects plus better evidence, not proof that the phone's original server error was a specific subscription limit or invalid key.
