# TF Asset V4.0.2 market bridge repair

Base: V4.0.1 native SaiETF migration, commit 5bff99806bee76b602803cd73b81746b3aab4e85.
Verified V3.2.49 ancestor: 2e9888518406fceefade70da3aefd542bb7a4f00.
Backup: backup-v4.0.1-20261007-pre-data-match.

## Root causes

1. Native bridge required LIVE for TWSE/Fugle trade provenance. A valid TWSE z older than 30 seconds was serialized as TWSE_MIS + backup_realtime. The App deliberately rejects this retired provenance, so nine valid native prices could become zero App quotes.
2. SQLite cold snapshots lacked market/statusMessage required by the same App validator and used a separate freshness/provenance mapping.
3. Persisted snapshots never hydrated the SaiETF memory store. After a partial provider response, previously persisted symbols disappeared from the published snapshot.
4. Providers could replace missing source clocks with the receipt clock. TWSE d/t source time and Yahoo regularMarketTime must remain the source clock.

## Changes

One native mapper supplies warm snapshots and market-only SQLite snapshots. TWSE z/Fugle trades retain actual-trade provenance regardless of age; quoteStatus separately retains LIVE/DELAYED/STALE/OFFLINE. Yahoo remains explicitly backup provenance, never official close. Only TWSE z supplies officialTradePrice.

Original-provider cache restores into the existing memory center with a seven-day age limit and future/trial/invalid-price rejection. Partial refresh preserves restored symbols. The native facade serializes concurrent refreshes. Existing source timestamp arbitration, provider circuit breaker and all immutable accounting code remain intact.

MIS source time prefers validated Taipei d/t; absent provider clocks are not replaced with the current time. Valid exchange/volume metadata is propagated. Cold and warm snapshots carry the same required fields. Persisted intraday sessions remain available separately from valuation.
