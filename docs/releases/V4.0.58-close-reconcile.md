# V4.0.58 — 收盤行情補核對與外部顯示最後快照

基底：V4.0.57 / 40057，commit `25f4b4ff66cd50f2327b7d4b07e948c54d09cf15`。
版本：4.0.58 / 40058。修護分支：`v4.0.58-close-reconcile`。

## 問題與證據

手機 16:34 的浮動行情牆仍顯示 0050 來源時間 12:51:41、00406A 12:51:40。圖片只能證明顯示時間停留，不能單憑圖片判定 Fugle 伺服器錯誤或盤中斷訊原因。

V4.0.57 在 13:30 排程結束立即暫停訂閱並停止背景寫入服務；`refresh()` 在允許時段之外直接回傳快取。沒有收盤補核對，因此漏收後段交易會一直保留。正式 Runtime 的測試在恢復舊的盤後 cache-only guard 後出現「Actual runtime must repair 12:51 cache on 16:34 refresh」，新版通過相同斷言。

## 修護行為

- 僅完整 13:30 排程、有效交易星期、非官方休市日且排程已啟用，才進行當日收盤補核對。較早自訂結束時段、停用與休市不會繞過使用者設定。
- 排程結束先停止串流，保留現有背景寫入服務，於收盤後 5 秒單次向同一 Fugle REST 來源核對。盤後啟動／回前景與持股清單載入完成，也會透過此流程補核對尚未確認的標的。
- 只有真實最後成交、可信來源時間、同日且 `isClose=true` 的結果進入原有行情中心仲裁。來源時間維持最後成交時間，絕不改成現在時間。
- 同日已確認收盤不重複請求。失敗只在後續生命週期事件重試，60 秒冷卻；没有價格輪詢計時器。單次工作有 15 秒請求預算，只對實際派發的標的記錄冷卻，未派發的標的優先處理。
- 背景服務等待相同或更新版本的 App 帳務快照寫入外部顯示後才停止；沒有寫入回覆也會在 30 秒內結束。過期關閉回呼不能停止重新恢復的連線。
- 快取寫入統一由一個序列化 writer，在鎖內取得目前 hot store；舊寫入不能晚於新收盤寫入而覆蓋它。
- 診斷增加 `SESSION_CLOSE`，只記錄所需／已確認數量與結果，不記錄 API key、代號、價格或帳務資料。

## 保護範圍

帳務公式、Finance Core、凍結 MarketDataCenter／MarketArbitrator、設定主頁 UI／分類／資料與行情牆版面保持原樣。設定頁只遞增 VERSION／BUILD。TF Asset 自行連接 Fugle，沒有外部 SaiETF 中繼。無需清除資料或卸載。

## 驗證

- 正式 Kotlin close reconciler：舊價格補回、原始來源時間、已確認不重複、停用／自訂時段／週末、失敗冷卻、未確認回覆、慢請求下未派發標的公平性。
- 正式 Kotlin process owner：持股尚未載入的啟動順序、最後版本 ACK、重複事件、回前景重試、舊回呼、無回覆期限。
- 正式 Runtime＋REST parser＋quote sink＋行情中心：16:34 開啟仍保留 12:51 快取的修護、發送版本、同步持久化、再次刷新不重複、停用、診斷內容。
- 正式 persistence controller：受控的旧寫入／收盤寫入重疊。舊實作 RED，新版 GREEN。
- 獨立程式審查的三項問題均已修正，複審無重大未決問題。

手機持續 Fugle 收訊、OEM 背景生命週期及實際收盤資料仍待真機確認；這次修護不代表圖片中的盤中斷訊根因已被確診。
